# Quality Attributes And Decisions

## 1. 质量目标

| 质量属性 | 目标 |
|---|---|
| 可恢复性 | 导入错误可追踪，下载失败有记录，不留下难以判断的静默失败。 |
| 数据一致性 | 重复导入不产生重复活动链接；链接变化时保留历史。 |
| 可维护性 | CLI、导入、数据库、MEGAcmd 集成模块边界清晰。 |
| 可测试性 | 核心规则可脱离真实 MEGAcmd 和完整 Excel 文件测试。 |
| 可用性 | 查询和下载命令输出明确，失败原因可理解。 |
| 性能 | 支持约 7.5 万行 Excel 导入和本地快速查询。 |

## 2. 关键设计决策

### 决策 1：使用 SQLite

理由：

- 单机工具无需数据库服务。
- 支持事务、索引和足够的数据规模。
- 文件可备份、迁移和排查。

代价：

- 不面向多用户并发写入。
- 大规模全文搜索能力有限，后续可用 FTS5 增强。

### 决策 2：内部字段使用 `work_code`

理由：

- 源列名 `RJcode` 与实际数据不完全一致。
- 内部命名更准确，减少未来支持 `VJ`、`BJ`、`d_` 等编码时的歧义。

代价：

- 导入层需要维护明确字段映射。

### 决策 3：保留历史下载链接

理由：

- 工作簿更新可能改变链接。
- 历史记录有助于排查链接变化。
- 用户默认只看活动链接，不受旧数据干扰。

代价：

- 数据库体积会随更新增长。
- 查询必须始终过滤 `is_deleted = 0`。

### 决策 4：默认排除 `.par2`

理由：

- `.par2` 常用于校验或恢复，但会增加下载体积。
- 默认下载主内容可降低磁盘压力。
- 通过 `--include-par2` 保留完整性选择。

代价：

- 需要在下载前明确提示哪些文件被排除。

### 决策 5：下载前强制检查 MEGAcmd 和磁盘空间

理由：

- 避免已知不可成功的下载消耗时间和网络。
- MEGAcmd 登录状态问题可以提前暴露。
- 磁盘不足时给用户明确的 required/free 数字。

代价：

- 下载流程稍长。
- 磁盘空间仍可能在下载过程中被其他进程消耗。

## 3. 测试策略

优先测试核心规则：

- 尺寸解析：`B`、`KB`、`MB`、`GB`。
- 声优拆分：单人、连续空格、日文顿号、逗号。
- MEGA JSON 解析：正常、非法 JSON、缺失字段、非法 size。
- 导入幂等：同一小样本导入两次不重复。
- 链接更新：旧活动链接变为 deleted，新链接可见。
- 查询：作品编码精确查询、声优模糊查询、社团模糊查询。
- 下载前置检查：MEGAcmd 缺失、未登录、空间不足、空间充足。

测试分层：

- 单元测试覆盖解析和计算。
- 集成测试使用小型 xlsx fixture 和临时 SQLite。
- MEGAcmd 使用 mock subprocess，不依赖真实网络。

## 4. 主要风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 工作簿表头变化 | 导入失败 | 按表头名校验并输出缺失列。 |
| 链接 JSON 根分组变化 | 漏导链接 | 遍历根分组并存储 `link_group`。 |
| 声优分隔符不一致 | 查询召回不足 | 保留 raw 字段，解析规则可迭代。 |
| MEGAcmd 状态不稳定 | 下载失败 | 下载前执行 `mega-whoami` 并记录失败摘要。 |
| 磁盘估算不足 | 下载中断 | 默认增加 5% 或至少 512 MB 安全余量。 |
| 导入速度偏慢 | 用户等待长 | read-only streaming、事务、索引，必要时批量优化。 |

## 5. 待确认问题

进入详细设计或实现前建议确认：

1. `download <work_code>` 默认是否下载所有非 `.par2` 活动文件。
2. 是否需要交互式选择单个文件，还是 v1 只提供 include/exclude `.par2`。
3. 查询结果是否默认显示成人内容标题，或需要 quiet mode。
4. `search-voice` 和 `search-circle` 的默认结果上限是否采用 50。
5. 是否需要把 `tags` 在 v1 就规范化成独立表。

## 6. 阶段交付边界

概要设计完成后，下一阶段可进入详细设计或直接实现 v1 骨架。

建议优先实现顺序：

1. 项目骨架、配置和数据库初始化。
2. Excel 导入和幂等测试。
3. 查询命令。
4. MEGAcmd 诊断和下载前置检查。
5. 下载执行和下载记录。
